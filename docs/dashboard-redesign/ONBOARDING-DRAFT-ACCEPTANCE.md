## Current journey

`/salon/onboarding/import` uses the existing salon session. The authenticated owner supplies permitted source text or manually enters identity, services/prices, hours, photos from that business's saved gallery, team and policies. An Instagram handle or website URL is provenance, not proof of ownership and not a request to scrape it. The current text parser recognizes explicit labels in English, French, Spanish and Simplified Chinese; it is deterministic and is **not AI**. Unrecognized source lines and absent facts remain unresolved.

Saving writes an owner-scoped private `business_onboarding_drafts` revision and reads it back. Six section reviews plus an explicit final confirmation are required before canonical records change. Confirmation accepts the draft ID/revision rather than resubmitting editable facts. A changed canonical workspace requires a newly saved review.

For an unpublished business, the canonical owner publication hold is applied before service-import triggers run. Supplied profile fields and hours update the existing salon, complete services pass through `import_salon_services_spreadsheet` and remain drafts, new stylist records remain inactive, and policies become a private canonical policy revision. Missing prices, durations or classifications never turn into free/default services. Existing services, staff and the current published policy are retained.

For an existing business, a separate acknowledgement explains immediate identity/hours/gallery changes and possible publication ineligibility after an address change. The owner's current hold remains unchanged; existing published records are not overwritten. New services, team and policies retain their separate review steps. Fresh publication state is returned separately from the immutable historical apply result.

The saved outcome links to the existing workspace, service/team/policy editors and reserved business/booking URL. Public availability continues to use the existing lifecycle, not a parallel publication system.

The separate **Create a new private draft with GC Assistant** action structures only owner-supplied text through the existing approved `gc_owner_assistant` model, active-plan/owner permission checks and `reserve_gc_assistant_usage` budget ledger. It neither changes either USD25 cap nor provides a separate AI allowance. No provider call runs automatically on load or refresh. The source is treated as data, not executable instructions; no website, Instagram or other-business lookup is available to the model. Sensitive phone/email/payment-like tokens are redacted before the provider request; an explicitly labeled business phone can be copied locally.

Every accepted suggested field carries an exact source quote. Fabricated values, truncated numeric fragments, unknown currencies, price range endpoints, from/plus prices, invented hours, IDs and application actions are rejected or left unknown. This bounded request supports up to12 services and8 team members; the full source remains available for manual review. Policy clauses remain source excerpts requiring the existing policy editor; photos remain restricted to the authenticated business's library. The AI result saves a separate private draft, retains original extraction evidence through subsequent owner edits, and still requires all six section reviews and final confirmation. Failed AI requests retain the entered text and leave manual setup available without being mislabeled as AI success.

Use the official Instagram API with Instagram Login for an authenticated professional account. Meta's official collection identifies Business/Creator accounts, the `instagram_business_basic` permission family and that this login option does not require a linked Facebook Page. Start with the minimum read permission necessary for the account's own profile/media; do not request publishing, messaging or comment permissions for onboarding. [Meta's official Instagram collection](https://www.postman.com/meta/instagram/folder/6raa77c/instagram-api-with-instagram-login).
