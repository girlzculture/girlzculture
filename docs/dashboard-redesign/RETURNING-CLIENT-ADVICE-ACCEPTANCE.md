## Implemented behavior

Bookings now contains a four-language returning-client check-in. Its visible suggestion uses at least three completed visits since the stated lookback start, no completed visit for at least 42 local calendar days, and no active future or in-service appointment in the authorized records. The exact business-time-zone date window is displayed: the start is 365 calendar days before today, and today is included through the check time. This is a labeled recommendation criterion, not a new platform policy or a prediction. Recorded completion timestamps take precedence; older records without them use the scheduled date of their completed appointment.

Customer accounts and the existing owner-approved guest-visit links establish identity. Names, matching email addresses and another business’s records never join histories. Each candidate opens the existing booking/client-history route; up to 20 clients are shown with complete counts and an explicit excerpt notice. Assigned professionals see only their permitted appointments, with that limitation stated. Empty verified history, no matching clients, incomplete/capped evidence and denied access remain distinct. Refresh removes older identities and links while a new request is pending or fails. The optional owner link opens the existing consent-aware client-update review; it does not select recipients or send anything.

The assistant’s existing business-summary read receives only aggregate counts, criteria, dates and the Bookings destination. No client identities, account IDs, link groups or contacts enter the model through this advice. The summary rechecks both booking and client-history permissions, refreshes underlying evidence for follow-ups, and removes old transcript facts when either permission is lost. Both $25 caps and the assistant tool vocabulary are unchanged.
