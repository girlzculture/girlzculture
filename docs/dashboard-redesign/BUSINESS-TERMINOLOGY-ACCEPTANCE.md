# Reviewed beauty and business terminology

The [founder clause](founder-software-first-2026-09-18.md#L614) asks for a reviewed beauty/business glossary. It does not require a hosted DeepL glossary. Version `2026-09-19.1` in [business-terminology.ts](../../src/i18n/business-terminology.ts) provides 26 immutable terms, four domains and EN/FR/ES/Simplified Chinese. The existing assistant's answer phase now receives its bounded guidance under the conditions below. Status: **AUTOMATED ONLY**; compiled release and hosted language-quality acceptance remain outstanding. DeepL is unchanged.

## Meaning and provenance

Labels are pinned to existing finance, owner, deposit and product catalogs and compared against those sources by tests. The single deliberate contextual variant is Spanish **Payout → Desembolso**, derived from the existing **Payout status → Estado del desembolso**. The older generic **Cobro** overlaps customer receipts. This module does not replace the existing UI catalog or alter saved records.

The definitions distinguish deposits, balances still outstanding, received payments, service sales, recorded profit, provider payouts, accrued staff compensation, compensation paid and refunds. They retain verification, missing-cost, date and agreement qualifications. A recorded no-show is distinct from a cancellation and authorizes no charge by itself. Physical **Picked up** is distinct from financial **Collected**. Generic service and hairstyle terms provide vocabulary, not service identity matching, a final quote or a duration inference.

Original business, person, service, product and option names, quoted source text and saved record labels take precedence, including names identical to glossary words. There is no search-and-replace API. Locale/domain are the only function inputs; no customer text, business records or provider credentials enter the module. Unsupported locales/domains return `null`; this adds no Wolof capability and does not remove existing language support elsewhere.

## Reviewed assistant answer integration

`assistantBusinessTerminologyGuidance(targetLocale, domain)` now appends static generic wording and preservation instructions to the existing **answer-only** system instructions in [gcAssistantPlanningServer.ts](../../src/lib/gcAssistantPlanningServer.ts). Literal tool-to-domain mappings use the current non-null, authorized read results. Only a single business-summary result may use a literal validated page-to-domain mapping. Mixed or unknown contexts omit guidance; user prose, model output and record fields cannot select a glossary domain. The resolved answer locale selects the wording. Planning receives no glossary block, and Wolof returns no glossary block without removing its existing language support.

The integration does not transform any result or original record text, broaden a permission, restore revoked data, change a model or raise either $25 cap. Existing fresh permission checks, record projections and output bounds remain authoritative. The guidance is included in the existing byte-length calculation and cost reservation, so it does not bypass the input budget. Captured requests verify the four required locales, exact original names/monetary amounts/currency/dates, and planning/Wolof/mixed-domain omission. Guidance cannot guarantee the quality of model-generated language.

## Separate translation context remains disconnected

`businessTranslationContext(sourceLocale, domain)` is separate natural domain prose in a **known source language**. DeepL documents context as surrounding content for disambiguation, not commands or enforced terminology. Context characters are not billed; the total request-body limit still applies. See the [official context guide](https://developers.deepl.com/docs/learning-how-tos/examples-and-guides/how-to-use-context-parameter). Therefore the assistant instruction block must never be sent as DeepL context. The module prepares compatible prose but makes no provider request and creates no hosted glossary.

The existing `translateWithDeepL` caller has no trusted source-locale/domain contract. Any later hook should add only these two allowlisted optional inputs, add static context when both are known, and preserve existing free-endpoint, budget, XML protection, timeout and no-retry behavior. Caller integration needs a provider-stub wire assertion, unknown-source omission, exact protected-token restoration and unchanged reservation/billing behavior. Arbitrary source text must not become an instruction or domain selector. Actual provider quality and native-speaker review remain unverified.
